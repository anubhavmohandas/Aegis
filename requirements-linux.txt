qtpy
# LINUX ONLY, and load-bearing here even though nothing in Aegis imports Qt
# directly: pywebview's window needs a GUI backend, and on Linux it has exactly
# two -- GTK (PyGObject + WebKitGTK, apt packages a plain venv cannot see) or
# Qt. PySide6 ships QtWebEngineWidgets and qtpy is the thin shim
# `webview.platforms.qt` actually imports. Without these two lines
# `python desktop_app.py` dies at start() with "You must have either QT or GTK
# with Python extensions installed" -- verified: qtpy alone makes that import
# resolve to PySide6/qtwebengine.
#
# It used to sit in requirements-common for ui/timeline_app.py (a read-only
# PySide6 timeline viewer, since deleted -- the dashboard superseded it). That
# made every macOS and Windows install pay for a Qt runtime that
# packaging/aegis.spec then excluded from the bundle anyway.

# Not pip-installable -- install with apt (Debian/Kali/Ubuntu):
#
#   sudo apt install python3-tk libnotify-bin
#
#   python3-tk    -- backs the Stop Monitoring / Quit password prompt
#                    (desktop_app._prompt_password_tk). Debian-family pythons
#                    ship WITHOUT tkinter, and the tamper gate fails closed:
#                    with no dialog available the window refuses to close and
#                    the only way out is killing the process (or turning off
#                    tamper protection in Settings first).
#   libnotify-bin -- provides notify-send, which core/notifier.py calls
#                    directly for desktop popups; only matters with
#                    notify_enabled: true. Without it notifications fall back
#                    to a printed line, nothing else breaks.
#
# QtWebEngine also needs the usual Chromium runtime libs (libnss3,
# libxkbcommon-x11-0, libxcomposite1, libxdamage1, libasound2t64). A normal
# Kali/GNOME/XFCE desktop already has them; a minimal or headless install
# doesn't -- `python main.py` (tray/headless, no window) works there instead.
